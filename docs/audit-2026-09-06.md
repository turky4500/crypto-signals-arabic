## 🔴 1. أخطاء حرجة تُفسد صحة الإشارات

### 1.1 الماسح يحلل الشمعة **الجارية** غير المغلقة (Repainting)

`scanner.py` يجلب `klines` بدون `endTime`، فيكون **آخر عنصر هو الشمعة التي لم تُغلق بعد**. وتحققتُ من ذلك عملياً:

```
20:00 UTC  close= 79916.01   <-- الشمعة الجارية
NOW: 20:42:59 UTC
عمر آخر شمعة = 43.0 دقيقة  =>  الشمعة غير مغلقة = True
```

الـ cron يعمل عند **الدقيقة الخامسة** (`5 * * * *`)، أي أن كل المؤشرات (RSI, EMA, MACD, SuperTrend) تُحسب على شمعة عمرها **5 دقائق فقط** من أصل 60.

**الأثر المقاس:**

| المقياس | الشمعة الجارية (الحالي) | الشموع المغلقة فقط |
|---|---|---|
| عدد الإشارات | **105** | 97 |
| متوسط `volume_ratio` | 0.56x | 0.66x |
| أزواج تختلف بين الطريقتين | **20 زوجاً** | — |

**20 زوجاً تظهر وتختفي** حسب اللحظة التي يُشغَّل فيها الفحص — هذا تعريف إعادة الرسم بالضبط. إشارة تراها الآن قد لا تكون موجودة بعد ساعة، ولا يمكن إعادة إنتاجها أو backtesting-ها.

**الدليل في بياناتك المنشورة:** `signals.json` الحالي مرتّب تنازلياً حسب `volume_ratio`، ومع ذلك أعلى القيم هي:

```
SNX/USDT   → 0.34x
SHIB/USDT  → 0.28x
METIS/USDT → 0.19x
LA/USDT    → 0.10x
```

كلها **أقل من 1x** لأن الشمعة لم تكتمل. أي أن **الترتيب بأكمله ضجيج**، وعمود "السيولة" في الواجهة لا معنى له حالياً.

**الإصلاح:** تجاهل آخر شمعة، أو مرّر `endTime` لآخر ساعة مغلقة.

```python
frame = prepare_frame(raw).iloc[:-1].reset_index(drop=True)
```

### 1.2 معدل الإصابة 60.7% — ليست "إشارة" بل وصف للسوق

```
المرشحون: 173 زوجاً
إشارات:   105  =  60.7% من كل الأزواج
التوزيع:   A: 98   C: 7   B: 0
```

عندما تحقق **6 من كل 10 عملات** شرط "الشراء"، فالشرط لا يميّز شيئاً. سبب ذلك أن الاستراتيجية A:

```python
if row.close > row.ema200 and row.st_dir == 1 and 45 <= row.rsi <= 65:
```

تعني حرفياً: *"العملة في اتجاه صاعد"*. في سوق صاعد هذا ينطبق على الأغلبية. النطاق `45–65` واسع جداً ولا يوجد أي شرط على **قوة** الحركة أو **الحجم**.

**الإصلاح المقترح:**
- أضف شرط سيولة حقيقي: `vol_ratio > 1.5` **على شمعة مغلقة**.
- أضف شرط زخم: `roc_24h > 2%` أو `close > ema20 * 1.01`.
- أضف **سقف عدد الإشارات** (Top-N) بترتيب على نتيجة مرجّحة (score) بدل إغراق اللوحة.
- أضف حقلاً `score` من 0–100 ورتّب عليه.

### 1.3 الاستراتيجية B (تقاطع الزخم) **ميتة عملياً** — صفر إشارات

```python
if prev.ema20 <= prev.ema50 and row.ema20 > row.ema50 and row.vol_ratio > 1.5:
```

تقاطع EMA20/EMA50 يقع في ساعة واحدة باحتمال منخفض (~1%)، **و** تشترط `vol_ratio > 1.5` على شمعة عمرها 5 دقائق (قيمها الحقيقية ~0.1). الشرطان معاً = **صفر إشارات دائماً**. زر الفلترة "تقاطع الزخم" في الواجهة لن يُظهر شيئاً أبداً.

**الإصلاح:** افحص التقاطع خلال آخر N شموع (مثلاً 3) بدل ساعة واحدة، واحسب `vol_ratio` على الشمعة المغلقة.

## 🟠 2. ثغرات في CI/CD

### 2.1 تشغيل Pages الأول **فشل فعلاً**

```
نشر لوحة GitHub Pages #1 : Commit 6e2a043 : 11s : ❌ failure
نشر لوحة GitHub Pages #2 : Manual run     : 18s : ✅ success
```

السبب المعتاد: `Settings → Pages → Source` لم يكن مضبوطاً على **GitHub Actions** وقت التشغيل الأول. أنت أصلحته يدوياً وإعادة التشغيل نجحت، **لكن شارة `failure` ما زالت ملتصقة بآخر commit** في صفحة المستودع.

**الإصلاح:** من `Actions → نشر لوحة GitHub Pages #1 → Re-run failed jobs` لتنظيف الشارة، أو اعمل commit فارغ.

### 2.2 لا يوجد `timeout-minutes` ولا `concurrency` في `scanner.yml`

لو عَلِق الماسح (شبكة بطيئة، 173 طلباً)، يستمر حتى الحد الأقصى (6 ساعات) ويستهلك دقائق Actions. ولو تجاوز التشغيل 60 دقيقة يتراكب تشغيلان ويحصل **تعارض push**.

```yaml
concurrency:
  group: scanner
  cancel-in-progress: false
jobs:
  scan:
    timeout-minutes: 15
```

### 2.3 `requirements.txt` غير مثبّت الإصدارات + `cache: pip`

```
requests>=2.31.0
pandas>=2.1.0
numpy>=1.26.0
```

`cache: pip` مع `>=` يعني أن **كاش pip لا يضمن تطابق البيئة**. إصدار pandas جديد (3.x مثلاً) قد يكسر `ewm`/`.iloc` ويسبب فشل صامت بعد أشهر.

**الإصلاح:** ثبّت الإصدارات أو أضف `requirements.lock` / `pip freeze`.

### 2.4 commit كل ساعة = تضخّم تاريخ المستودع

`scanner.yml` يعمل commit إلى `main` كل ساعة → **~8,760 commit في السنة**، وكل واحد يشغّل `pages.yml`. بعد سنة يصبح `git clone` بطيئاً والتاريخ غير قابل للقراءة.

**الإصلاح الأفضل:** اجعل `scanner.yml` يبني وينشر Pages مباشرة عبر `upload-pages-artifact` (بدون commit لـ `signals.json` في `main`)، أو اكتب البيانات إلى فرع `orphan` منفصل مثل `data`.

### 2.5 تحذير Node.js 20 في سجل التشغيل

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being
forced to run on Node.js 24: actions/checkout@v4, actions/configure-pages@v5,
actions/deploy-pages@v4, actions/upload-artifact@v4.
```

**الإصلاح:** ارفع إلى `actions/checkout@v5` و`actions/configure-pages@v6` و`actions/deploy-pages@v5`.

### 2.6 لا يوجد اختبار آلي للكود المالي

لا `tests/`، لا CI يشغّل pytest أو ruff. دوال مثل `rsi()` و`supertrend()` **حسابات مالية حساسة** بدون أي اختبار يتحقق من صحتها مقابل قيم مرجعية معروفة.

## 🟡 3. نواقص في الواجهة (`index.html`)

### 3.1 Tailwind عبر CDN — غير صالح للإنتاج

```html
<script src="https://cdn.tailwindcss.com"></script>
```

هذا **مصرّح رسمياً بأنه للتطوير فقط**: يجلب ~300–400KB من JS ويبني CSS في المتصفح عند كل تحميل. أضف إليه Google Fonts → الصفحة تعتمد على **3 نطاقات خارجية** قبل أن تعرض حرفاً واحداً.

**الإصلاح:** ابنِ CSS مرة واحدة (`npx tailwindcss -i in.css -o style.css --minify`) والتزمه في المستودع (~15KB).

### 3.2 العدّاد التنازلي **مزيّف**

```js
let nextUpdate = Date.now() + 3600000;
```

يُحسب من **لحظة فتح الصفحة**، لا من وقت الفحص الفعلي (الدقيقة الخامسة كل ساعة). لو فتحت الصفحة الساعة 20:50 سيقول "التحديث القادم خلال 60 دقيقة" بينما التحديث الحقيقي بعد 15 دقيقة.

**الإصلاح:** احسبه من `timestamp` في البيانات:

```js
const last = new Date(d.timestamp).getTime();
nextUpdate = Math.ceil((last + 3600000) / 3600000) * 3600000;
```

### 3.3 لا تمييز بين "لا إشارات" و"فشل تحميل"

```js
catch(e){ $('updated').textContent='في انتظار أول فحص'; $('empty').classList.remove('hidden') }
```

عند أي خطأ شبكة تظهر نفس رسالة **"لا توجد إشارات دخول متحققة حالياً"**. المستخدم يظن السوق هادئاً بينما البيانات لم تصل. لا يوجد retry ولا زر إعادة تحميل يدوي.

### 3.4 الواجهة تعرض حقلاً مشوّهاً ولا تعرض الأهم

- عمود **"السيولة"** يعرض `volume_ratio` المحسوب على شمعة ناقصة (انظر 1.1) — بلا معنى حالياً.
- **لا يوجد** تغيّر سعر 24h، لا sparkline، لا هدف/وقف.
- الجدول **غير قابل للترتيب** بالنقر على العناوين.
- دالة `badge(code, name)` تستقبل `name` ولا تستخدمه — معامل ميت.
- `$('total').textContent = allSignals.length` يشمل التكرار (انظر 1.5) → رقم مضخّم.

### 3.5 نواقص صفحات وSEO

لا `favicon.ico`، لا `404.html` (Pages يحتاجه للمسارات الخاطئة)، لا Open Graph / `twitter:card` (الرابط يظهر بلا صورة عند المشاركة)، لا `manifest.json` / PWA.

## 🟠 5. نواقص وظيفية — ما ينقص المشروع كمنتج

### 5.1 لا يوجد إدارة مخاطر (الأهم تداولياً)

حقول الإشارة الفعلية:

```
pair, symbol, price, rsi, volume_ratio, quote_volume_24h, strategy, strategy_code, reason
```

**لا يوجد:** `stop_loss`، `take_profit`، `side`/`direction`، `timeframe` لكل إشارة، `entry_zone`، `risk_reward`.

"إشارة شراء" بلا وقف وخروج ليست إشارة — هي ملاحظة. **هذا أكبر نقص وظيفي.**

**الإصلاح:** احسبها من ATR الموجود أصلاً في `supertrend()`:

```python
"stop_loss":   round(price - 1.5 * atr, 8),
"take_profit": round(price + 3.0 * atr, 8),
"risk_reward": 2.0
```

### 5.2 لا يوجد backtesting

ثلاث استراتيجيات بعتبات مختارة يدوياً و**لا دليل واحد** على أنها مربحة. بدون اختبار تاريخي، المشروع يولّد أرقاماً لا معنى لها.

**الإصلاح:** `backtest.py` يشغّل الاستراتيجيات على 6–12 شهراً ويعرض win rate، متوسط الربح/الخسارة، Sharpe، max drawdown.

### 5.3 لا يوجد سجل تاريخي للإشارات

كل دورة **تمسح** ما قبلها. لا يمكن معرفة: هل إشارة BTC قبل 3 أيام نجحت؟ كم إشارة تحققت هذا الأسبوع؟

**الإصلاح:** ألحق بـ `history/signals-YYYY-MM.jsonl`، واعرض في الواجهة "أداء الإشارات السابقة".

### 5.4 لا يوجد إشعارات

مشروع إشارات بلا push = يجب أن تفتح الموقع كل ساعة.

**الإصلاح:** خطوة في `scanner.yml` ترسل إلى **Telegram Bot** أو Discord Webhook عند ظهور إشارة جديدة فقط (مقارنة بالدورة السابقة). السرية عبر GitHub Secrets.

### 5.5 لا كشف "الجديد" مقابل "القديم"

الإشارة التي ظهرت قبل 5 ساعات وما زالت شروطها قائمة تُعرض كأنها طازجة. لا حقل `first_seen` ولا `age_hours`.

### 5.6 اتجاه واحد فقط

الماسح يلتقط **إشارات شراء** فقط. لا إشارات بيع/خروج، ولا تحذيرات انهيار — رغم أن كل المؤشرات المحسوبة تدعم ذلك.

### 5.7 `KLINE_LIMIT = 250` مع `EMA200`

الحد الأدنى في `analyze` هو 210 شمعة، و`ema200` يحتاج `min_periods=200`. بجلب 250 شمعة فقط، تكون أول ~50 قيمة لـ EMA200 **غير متقاربة** (تعتمد على نقطة البداية). القيمة عند الشمعة الأخيرة مقبولة تقريباً، لكن الهامش ضيق جداً.

**الإصلاح:** ارفع `KLINE_LIMIT` إلى 400–500 لتقارب سليم.

### 5.8 `supertrend()` حلقة Python بطيئة

## ✅ 6. ما هو **جيد** في المشروع (للإنصاف)

- كود Python نظيف ومنظم، مع type hints و`from __future__ import annotations`.
- `get_json()` فيها retry مع احترام `Retry-After` لـ 418/429 — **معالجة صحيحة لمعدلات Binance**.
- حساب RSI بـ Wilder's smoothing (`alpha=1/period`) — **الصيغة الصحيحة**، ليس المتوسط البسيط الشائع الخاطئ.
- SuperTrend مُنفَّذ بطريقة ATR التقليدية الصحيحة.
- لا يحتاج مفاتيح API خاصة → **لا خطر على أموال المستخدم**. تصميم آمن.
- `permissions: contents: write` مقيّدة في workflow واحد فقط (مبدأ أقل الصلاحيات).
- `git diff --cached --quiet || git commit` → لا commits فارغة. جيد.
- الواجهة RTL عربية حقيقية، تصميم داكن أنيق، و`prefers-reduced-motion` محترم (تفاصيل وصولية ممتازة).
- `fetch('./signals.json?ts='+Date.now())` → cache-busting صحيح يتجاوز `max-age=600` الخاص بـ Pages.
- إخفاء الأخطاء على مستوى الزوج الواحد يمنع انهيار الدورة كاملة (مع تحفّظ 1.6).
- الموقع **منشور ويعمل فعلاً**: HTTP 200 على `index.html` و`signals.json`.
